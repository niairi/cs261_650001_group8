# System Test Cases

## Flow 1: เข้าสู่ระบบ → ดูตารางห้อง → จองห้อง → ได้รับอีเมลยืนยัน

**User Stories:** US1 → US2 → US3 → US5

| Test ID | ขั้นตอน | การดำเนินการ | ผลลัพธ์ที่คาดหวัง |
|---|---:|---|---|
| SYS-01 | 1 | เข้าสู่ระบบด้วยบัญชีผู้ใช้ที่ถูกต้อง | ผู้ใช้สามารถเข้าสู่ระบบและเข้าใช้งานระบบได้สำเร็จ |
| SYS-01 | 2 | ดูตารางการใช้ห้อง | ระบบแสดงข้อมูลห้องและตารางการจอง |
| SYS-01 | 3 | เลือกห้องที่ว่างและทำการจอง | ระบบสร้างรายการจองสำเร็จ |
| SYS-01 | 4 | ตรวจสอบอีเมลยืนยันการจอง | ผู้ใช้ได้รับอีเมลยืนยันการจองสำเร็จ |

**ผลลัพธ์โดยรวมที่คาดหวัง:**  
ผู้ใช้สามารถดำเนินการตั้งแต่เข้าสู่ระบบ ดูตารางห้อง ทำการจองห้อง และได้รับอีเมลยืนยันการจองได้สำเร็จ

## 3. Sprint 2 System Test Cases

ส่วนนี้เพิ่มเติมสำหรับ Task 71 โดยครอบคลุม System Test ของ **US5 TC3, US6–US15 และ UI v2**

### Flow 3: จองสำเร็จ → ตรวจสอบกรณีส่งอีเมลไม่ได้

**User Stories:** US5 TC3

| Test ID | ขั้นตอน | การดำเนินการ | ผลลัพธ์ที่คาดหวัง |
|---|---:|---|---|
| SYS-03 | 1 | จำลองให้เซิร์ฟเวอร์อีเมลใช้งานไม่ได้ | ระบบไม่สามารถส่งอีเมลได้ |
| SYS-03 | 2 | ผู้ใช้ทำการจองห้องและยืนยันการจอง | ระบบบันทึกการจองสำเร็จ |
| SYS-03 | 3 | ตรวจสอบผลการส่งอีเมล | ระบบบันทึกผลการส่งอีเมลเป็น `FAILED` ใน `email_logs` |
| SYS-03 | 4 | ตรวจสอบข้อมูลการจองหลังการส่งอีเมลล้มเหลว | ข้อมูลการจองยังคงถูกบันทึก และระบบบันทึกผลการส่งอีเมลล้มเหลวตามเงื่อนไข |

**ผลลัพธ์โดยรวมที่คาดหวัง:**  
เมื่อเซิร์ฟเวอร์อีเมลใช้งานไม่ได้ ระบบยังสามารถบันทึกการจองได้ และบันทึกผลการส่งอีเมลเป็น `FAILED` ใน `email_logs`

### Flow 4: แก้ไขการจอง → ตรวจสอบรายการจอง

**User Stories:** US6

| Test ID | ขั้นตอน | การดำเนินการ | ผลลัพธ์ที่คาดหวัง |
|---|---:|---|---|
| SYS-04 | 1 | เข้าสู่ระบบและเปิดรายการจองของตนเอง | ระบบแสดงรายการจองของผู้ใช้ |
| SYS-04 | 2 | เลือกรายการจองที่ต้องการแก้ไข | ระบบแสดงข้อมูลการจองเดิม |
| SYS-04 | 3 | แก้ไขวันหรือเวลาการจอง | ระบบตรวจสอบเงื่อนไขและบันทึกข้อมูลใหม่สำเร็จ |
| SYS-04 | 4 | ตรวจสอบรายการจองหลังแก้ไข | ระบบแสดงข้อมูลการจองที่ถูกแก้ไขแล้วอย่างถูกต้อง |

**ผลลัพธ์โดยรวมที่คาดหวัง:**  
ผู้ใช้สามารถแก้ไขรายการจองของตนเอง และตรวจสอบได้ว่าข้อมูลการจองถูกปรับปรุงเรียบร้อยแล้ว

### Flow 6: เข้าห้อง → Check-in → ยืนยันการใช้งาน

**User Stories:** US8

| Test ID | ขั้นตอน | การดำเนินการ | ผลลัพธ์ที่คาดหวัง |
|---|---:|---|---|
| SYS-06 | 1 | ผู้ใช้มีรายการจองที่ถึงเวลาใช้งาน | ระบบแสดงรายการจองที่สามารถ Check-in ได้ |
| SYS-06 | 2 | ผู้ใช้อยู่ภายในระยะ 5 เมตรจากห้อง | ระบบสามารถตรวจสอบตำแหน่งของผู้ใช้ได้ |
| SYS-06 | 3 | ผู้ใช้กด Check-in | ระบบยืนยันการ Check-in สำเร็จ |
| SYS-06 | 4 | ตรวจสอบสถานะการจอง | Booking ถูกเปลี่ยนเป็นสถานะ `CONFIRMED` และบันทึกเวลา Check-in |

**ผลลัพธ์โดยรวมที่คาดหวัง:**  
ผู้ใช้สามารถ Check-in ได้เมื่ออยู่ภายในระยะที่กำหนด และระบบบันทึกการยืนยันการใช้งานห้องอย่างถูกต้อง

### Flow 7: ไม่ Check-in → No-show → ถูกระงับสิทธิ์การจอง

**User Stories:** US9 → US10

| Test ID | ขั้นตอน | การดำเนินการ | ผลลัพธ์ที่คาดหวัง |
|---|---:|---|---|
| SYS-07 | 1 | ผู้ใช้มีรายการจองแต่ไม่ Check-in ภายในเวลาที่กำหนด | ระบบตรวจพบว่าผู้ใช้ไม่มาใช้งาน |
| SYS-07 | 2 | ตรวจสอบสถานะ Booking | ระบบเปลี่ยนสถานะ Booking เป็น `EXPIRED` |

| SYS-07 | 4 | ผู้ใช้พยายามจองห้องระหว่างถูก Blacklist | ระบบปฏิเสธการจองและแจ้งว่าผู้ใช้ถูกระงับสิทธิ์ |

**ผลลัพธ์โดยรวมที่คาดหวัง:**  
ระบบสามารถตรวจจับ No-show นับจำนวนครั้ง และระงับสิทธิ์การจองของผู้ใช้เมื่อครบตามเงื่อนไขได้ถูกต้อง
