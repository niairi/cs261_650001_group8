# UAT Report – Sprint 2

## 1. Objective

เพื่อทดสอบการยอมรับระบบ TU CS Space ใน Sprint 2 โดยให้ผู้ทดลองใช้กลุ่มเดิมจาก Task53 กลับมาทดลองใช้งานเว็บไซต์เวอร์ชันใหม่ (UI v2) และฟีเจอร์ US5 TC3, US6–US15 เพื่อประเมินว่าระบบสามารถทำงานได้ถูกต้องตามความต้องการของผู้ใช้หรือไม่ รวมถึงตรวจสอบว่าปัญหาที่พบจากการทดสอบรอบแรกได้รับการแก้ไขแล้วหรือไม่

## 2. Scope

การทดสอบครอบคลุมการใช้งาน UI v2 และฟีเจอร์ Sprint 2 ดังนี้

| User Story | รายละเอียด |
|---|---|

| US6 | แก้ไข Booking และตรวจสอบเงื่อนไขการแก้ไข |
| US7 | จัดการ Booking สำหรับ Admin |

## 3. Feedback Collection

### 3.1 ข้อมูลการทดสอบ

- วันที่ทดสอบ: 16 พฤศจิกายน 2569
- จำนวนผู้ทดลองใช้: 6 คน
- กลุ่มผู้ทดลองใช้: นักศึกษาสาขาวิทยาการคอมพิวเตอร์ วิชา CS261
- วิธีการทดสอบ: ให้ผู้ทดลองใช้ทดลองใช้งานเว็บไซต์ UI v2 และฟีเจอร์ Sprint 2 พร้อมสังเกตพฤติกรรมและสัมภาษณ์หลังทดลองใช้
- อุปกรณ์: Desktop และ Mobile

### 3.2 ขั้นตอนการทดสอบ

1. ให้ผู้ทดลองใช้เข้าสู่ระบบ
2. ทดลองใช้งาน UI v2 และตรวจสอบการแสดงผล

4. ทดลองแก้ไข Booking
5. ทดลองใช้งานหน้า Admin
6. ทดลอง Check-in ตามเงื่อนไขต่าง ๆ
7. ตรวจสอบการทำงานของระบบ No-show และ Blacklist โดยจำลอง UAT-17, UAT-21 และ UAT-23 ในรอบทดสอบเดียวกันด้วยข้อมูล seed ที่เตรียมไว้ล่วงหน้า เช่น ผู้ใช้ทดสอบคนเดียวกันที่มี 3 รายการ No-show และกำหนดเวลา Blacklist ให้สิ้นสุดภายในรอบจำลอง โดยไม่รอเวลาจริง 30 วัน
8. ตรวจสอบปุ่ม Logout และยืนยันว่าออกจากระบบแล้ว
9. รวบรวมความคิดเห็นและข้อเสนอแนะ
10. เปรียบเทียบผลกับ Feedback รอบแรกจาก Task 53

| Blacklist | การแจ้งเตือนเมื่อถูกระงับสิทธิ์ช่วยให้เข้าใจปัญหาได้ชัดเจน |

### 6.2 ข้อเสนอแนะเพิ่มเติม

1. ควรปรับระยะห่างระหว่างองค์ประกอบบน Mobile ให้เหมาะสมมากขึ้น
2. ควรทำข้อความแจ้งเตือนให้เข้าใจง่ายและชัดเจน
3. ควรจัดกลุ่มข้อมูลในหน้า Admin ให้ค้นหาได้สะดวก
4. ควรแสดงสถานะ Booking ให้เห็นได้ชัดเจน

### 7.1 สรุปผลการเปรียบเทียบ

## 9. Conclusion

จากการทดสอบ UAT ของระบบ TU CS Space ใน Sprint 2 พบว่า UI v2 มีการปรับปรุงจากข้อเสนอแนะของผู้ทดลองใช้ใน Task53 ได้อย่างเหมาะสม โดยเฉพาะการปรับขนาดฟอนต์เมนู การเพิ่มการแสดงเวลาปัจจุบัน และการจัดวางองค์ประกอบบน Mobile

ในส่วนของ US5 TC3 และ US6–US15 ระบบผ่านการทดสอบตามเงื่อนไขที่กำหนด โดย US5 TC3 ทดสอบกรณี SMTP failure ด้วย mock (ไม่ได้ทดสอบกับ SMTP จริง) ส่วนฟีเจอร์อื่นครอบคลุมการแก้ไข Booking การจัดการ Booking สำหรับ Admin การ Check-in การตรวจสอบ No-show การจัดการ Blacklist การ Logout การจัดการห้อง การจัดการ Blacklist และเงื่อนไขการ Login

โดยสรุป การปรับปรุงใน Sprint 2 ช่วยให้ระบบมีความครบถ้วนและสะดวกต่อการใช้งานมากขึ้นเมื่อเทียบกับ Sprint 1 และสามารถนำข้อเสนอแนะเพิ่มเติมไปใช้พัฒนาระบบใน Sprint ถัดไปได้
