# Test Case Specification — TU CS Space

เอกสารกรณีทดสอบของระบบจองห้อง (Task20) อ้างอิง endpoint ใน [`API.md`](API.md)

แบ่งเป็น 2 ส่วน

| ส่วน | วิธีทดสอบ | จำนวน |
|---|---|---|
| A. Unit test อัตโนมัติ | `npm test` ใน `backend/` ไม่ต้องมีฐานข้อมูลหรืออินเทอร์เน็ต | 40 |
| B. ทดสอบด้วยมือ | เรียก API ด้วย Postman / curl และกดบนหน้าเว็บจริง | 41 |

---

## วิธีเตรียมทดสอบ

**Unit test**

```bash
cd backend
npm test          # ผลที่ถูกต้อง: tests 40, pass 40, fail 0
```

**ทดสอบด้วยมือ**

1. PostgreSQL รันอยู่ และสร้างตารางจาก `database/schema.sql`, `database/seed.sql`, `database/002_users_and_email_logs.sql`
2. ตั้ง `backend/.env` (ดู `.env.example`) แล้วรัน `npm run dev` ใน `backend/` ต้องขึ้น `Room booking API running on http://localhost:3000`
3. เปิด `frontend/login.html` ด้วย Live Server (`http://127.0.0.1:5500`)
4. บัญชีทดสอบ:
   - **นักศึกษา A** และ **นักศึกษา B**: บัญชี TU จริง 2 คน หรือเว้น `TU_API_KEY` ว่างเพื่อใช้โหมดจำลอง (รหัสผ่านอะไรก็ได้)
   - **Admin**: ใส่รหัสของคนนั้นใน `ADMIN_IDS`
5. ถ้ายังไม่ได้ตั้ง SMTP อีเมลจะแสดงใน terminal ที่รัน backend แทนการส่งจริง

ช่อง **ผล** ในส่วน B ให้กรอก ✅ ผ่าน / ❌ ไม่ผ่าน พร้อมวันที่และชื่อผู้ทดสอบ

## ยังไม่ได้ทดสอบ (รอทีมตัดสินใจหรือยังไม่มีระบบ)

- จำกัดการจองล่วงหน้าแค่วันนี้กับพรุ่งนี้ (backend ยังไม่ตรวจ)
- ยืนยันการเข้าใช้ห้องภายในระยะ 5 เมตร (`CONFIRMED`) และหมดอายุอัตโนมัติ (`EXPIRED`)
- ตรวจว่าผู้ใช้อยู่ภาควิชาวิทยาการคอมพิวเตอร์เท่านั้น
- unit test อัตโนมัติของ `routes/bookings.js`
