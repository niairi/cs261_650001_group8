## UC1 : การยืนยันตัวตนเข้าและออกจากระบบ (Login / Logout)

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor หลัก** | นักศึกษาสาขาวิทยาการคอมพิวเตอร์, เจ้าหน้าที่ภาควิชาฯ |
| **Actor รอง** | TU REST API (`/auth/Ad/verify`) |
| **คำอธิบาย** | ผู้ใช้เข้าสู่ระบบด้วย TU Account ระบบออก token และกำหนดบทบาท student / admin |
| **Pre-condition** | ผู้ใช้มี TU Account ที่ Active |
| **Post-condition** | ได้ token (อายุ 8 ชม. หรือ 7 วันถ้าติ๊ก "จดจำ") · บันทึก/อัปเดตข้อมูลผู้ใช้ในตาราง `users` |

**Main flow**
1. ผู้ใช้เปิดหน้า Login
2. กรอกเลขทะเบียนนักศึกษาและรหัสผ่าน (เลือกติ๊ก "จดจำการเข้าสู่ระบบ" ได้) แล้วกด Login
3. ระบบตรวจว่ากรอกครบ
4. ระบบส่งข้อมูลไปตรวจกับ TU REST API
5. TU REST API ยืนยันว่ารหัสถูก และส่งชื่อ อีเมล คณะ สาขากลับมา
6. ระบบกำหนดบทบาท (อยู่ในรายชื่อ `ADMIN_IDS` = admin, นอกนั้น = student)
7. ระบบบันทึก/อัปเดตข้อมูลผู้ใช้ในตาราง `users`
8. ระบบออก token และพาไปหน้าตารางห้อง พร้อมแสดงชื่อผู้ใช้มุมขวาบน

**Alternative flow**
- **3a กรอกไม่ครบ:** แสดงข้อความให้กรอกให้ครบ และไม่ส่งคำขอไป Backend (US1 TC3)
- **5a รหัสผ่านผิด:** แสดง "เลขทะเบียนนักศึกษาหรือรหัสผ่านไม่ถูกต้อง" (401) (US1 TC2)
- **5b ติดต่อ TU API ไม่ได้:** แสดง "ไม่สามารถเชื่อมต่อระบบของมหาวิทยาลัยได้" (502)
- **7a บันทึก users ไม่สำเร็จ:** login ยังผ่าน และเขียน error ไว้ใน log
- **token หมดอายุ / ไม่ถูกต้อง:** ระบบลบ token และพากลับหน้า Login

**ข้อจำกัด v1.0:** ยังไม่มีปุ่ม Logout บนหน้าเว็บ (ออกจากระบบได้เมื่อ token หมดอายุ) · ยังไม่ตรวจว่าเป็นสาขาวิทยาการคอมพิวเตอร์ (ย้ายไป Sprint 2) · เมนูของ Admin อยู่ใน UC6

## UC2 : ดูตารางห้องว่างและจองห้อง

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor หลัก** | นักศึกษาสาขาวิทยาการคอมพิวเตอร์ |
| **คำอธิบาย** | ดูสถานะห้องว่าง/ไม่ว่างแบบ Real-time แล้วเลือกห้อง วัน ช่วงเวลา และจองตามกฎของระบบ |
| **Pre-condition** | Login แล้ว |
| **Post-condition** | การจองถูกบันทึกสถานะ BOOKED · ช่วงเวลานั้นแสดง "ไม่ว่าง" (สีแดง) กับผู้ใช้ทุกคน · ส่งอีเมลยืนยัน (UC4) |

**Main flow**
1. ผู้ใช้เปิดหน้าจองห้อง
2. ระบบแสดงรายการห้องที่เปิดใช้งาน (Room A, B, C) และตารางสถานะของวันนี้และพรุ่งนี้ ช่วง 09:00–17:00 (ว่าง = เขียว, ไม่ว่าง = แดง)
3. ระบบรีเฟรชสถานะเองทุก 5 วินาที
4. ผู้ใช้เลือกห้อง วันที่ (ไม่เกิน 7 วันข้างหน้า) เวลาเริ่ม เวลาสิ้นสุด จำนวนคน และวัตถุประสงค์ แล้วกดยืนยัน
5. ระบบตรวจกฎ: 09:00–17:00 เต็มชั่วโมง, ไม่เกิน 3 ชม., ไม่ใช่เวลาที่ผ่านมาแล้ว, ไม่เกิน 7 วัน, จำนวนคนไม่เกินความจุ
6. ระบบตรวจว่าช่วงเวลาไม่ทับกับการจองอื่น
7. ระบบบันทึกการจอง และแสดง pop-up ยืนยันการจอง
8. ระบบส่งอีเมลยืนยัน (include UC4)

**Alternative flow**
- **2a โหลดข้อมูลไม่ได้:** แสดง "ไม่สามารถโหลดข้อมูลสถานะห้องได้ กรุณาลองใหม่อีกครั้ง" (US2 TC4)
- **5a ผิดกฎ:** แสดงข้อความตามกฎที่ผิด เช่น "จองได้ครั้งละไม่เกิน 3 ชั่วโมง", "จองล่วงหน้าได้ไม่เกิน 7 วัน", "จองได้เฉพาะช่วง 09:00 - 17:00 น." (400) (US3 TC3–TC6)
- **5b จำนวนคนเกินความจุ:** แสดง "ห้องนี้รองรับได้สูงสุด N คน" (400)
- **6a ช่วงเวลาถูกจองแล้ว:** แสดง "ช่วงเวลานี้มีผู้จองห้องนี้แล้ว" และไม่บันทึก (409) (US3 TC2)
- **4a token หมดอายุ:** แจ้งให้เข้าสู่ระบบใหม่และกลับหน้า Login (401)

## UC3 : จัดการการจองของฉัน (ดูรายการ / ยกเลิก / แก้ไขเวลา)

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor หลัก** | นักศึกษาสาขาวิทยาการคอมพิวเตอร์ |
| **คำอธิบาย** | ดูรายการจองของตัวเอง และยกเลิกการจองก่อนเวลาเริ่มอย่างน้อย 30 นาที (แก้ไขเวลาอยู่ Sprint 2 : US6) |
| **Pre-condition** | Login แล้ว · มีการจองสถานะ BOOKED |
| **Post-condition** | สถานะเป็น CANCELLED · ช่วงเวลากลับมาว่าง · ส่งอีเมลแจ้งการยกเลิก (UC4) |

**Main flow (ยกเลิก)**
1. ผู้ใช้เปิดหน้าประวัติการจอง
2. ระบบแสดงเฉพาะการจองของผู้ใช้ เรียงตามวันและเวลา แยกแท็บ ทั้งหมด / รอเข้าใช้งาน / ใช้งานเสร็จสิ้น / ยกเลิกแล้ว
3. ผู้ใช้กด "ยกเลิกการจอง"
4. ระบบแสดงหน้าต่างยืนยันการยกเลิก
5. ผู้ใช้กด "ยืนยันการยกเลิก"
6. ระบบตรวจว่าเป็นการจองของผู้ใช้ และเหลือเวลาก่อนเริ่มอย่างน้อย 30 นาที
7. ระบบเปลี่ยนสถานะเป็น CANCELLED (ไม่ลบข้อมูล เพื่อเก็บประวัติ) และแสดง "ยกเลิกการจองสำเร็จ"
8. ระบบส่งอีเมลแจ้งการยกเลิก (include UC4)

**Alternative flow**
- **3a เหลือไม่ถึง 30 นาที:** ปุ่มยกเลิกกดไม่ได้ และแสดง "ยกเลิกได้ก่อนเวลาเริ่มอย่างน้อย 30 นาที" (US4 TC4)
- **5a กด "กลับ":** ปิดหน้าต่าง สถานะไม่เปลี่ยน (US4 TC3)
- **6a ไม่ใช่การจองของตัวเอง:** ระบบปฏิเสธ (403) (US4 TC5)
- **6b ยกเลิกไปแล้ว / หมดอายุแล้ว:** แจ้งสถานะ (409)

## UC4 : แจ้งเตือนทางอีเมล

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor หลัก** | ระบบ (ถูกเรียกจาก UC2 และ UC3) |
| **Actor รอง** | SMTP Server (nodemailer), ผู้ใช้ (ผู้รับอีเมล) |
| **คำอธิบาย** | ส่งอีเมลยืนยันเมื่อจองหรือยกเลิกสำเร็จ ไปยังอีเมล @dome.tu.ac.th ของผู้ใช้ และบันทึกผลการส่ง |
| **Pre-condition** | การจองหรือการยกเลิกสำเร็จแล้ว |
| **Post-condition** | อีเมลถูกส่ง · บันทึกผล SENT / FAILED / SKIPPED ในตาราง `email_logs` |

**Main flow**
1. ระบบสร้างหัวข้ออีเมล เช่น `[CS Co-Working] ยืนยันการจอง Room A (101) 22/10/2569 10:00–12:00` หรือ `[CS Co-Working] ยกเลิกการจอง ...`
2. ระบบสร้างเนื้อหา: หมายเลขการจอง ห้อง วันที่ (ภาษาไทย) เวลา รหัสนักศึกษา
3. ระบบส่งอีเมลผ่าน SMTP
4. ระบบบันทึกผล SENT ใน `email_logs`

**Alternative flow**
- **1a ไม่มีอีเมลผู้จอง:** ไม่ส่ง บันทึก SKIPPED (no-recipient)
- **3a ยังไม่ได้ตั้ง SMTP (โหมดทดสอบ):** แสดงเนื้อหาอีเมลใน log ของ backend แทน บันทึก SKIPPED (smtp-not-configured)
- **3b SMTP ส่งไม่ได้:** การจอง/ยกเลิกยังสำเร็จ บันทึก FAILED พร้อม error (US5 TC3)

## UC5 : Check-in และจัดการ No-show / Blacklist อัตโนมัติ (Sprint 2)

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor** | นักศึกษา, Scheduler (ระบบตั้งเวลาอัตโนมัติ) |
| **Pre-condition** | มีการจอง BOOKED ในวันนั้น |
| **Post-condition** | CONFIRMED หรือ EXPIRED (No-show) · อัปเดตจำนวน No-show / Blacklist |

**Main flow (วางแผน)**
1. ผู้ใช้เปิดรายการจองเมื่อถึงเวลา แล้วกด "ยืนยันการเข้าใช้งาน"
2. ระบบตรวจตำแหน่ง GPS ว่าอยู่ภายใน 5 เมตรจากห้อง
3. ระบบเปลี่ยนสถานะเป็น CONFIRMED

**Alternative flow (วางแผน)**
- **2a อยู่นอกระยะ / ไม่อนุญาตตำแหน่ง:** แจ้งเตือน ยืนยันไม่ได้
- **1a ไม่ยืนยันภายใน 15 นาทีหลังเวลาเริ่ม:** Scheduler เปลี่ยนเป็น EXPIRED และนับ No-show
- **1b No-show ครบ 3 ครั้ง:** ระงับสิทธิ์การจอง 30 วัน และส่งอีเมลแจ้ง (UC4)

## UC6 : เรียกดูรายงานการจองทั้งหมด (Sprint 2)

| หัวข้อ | รายละเอียด |
|---|---|
| **Actor** | เจ้าหน้าที่ภาควิชาฯ (Admin) |
| **Pre-condition** | Login ด้วยสิทธิ์ Admin |
| **Post-condition** | ไม่มีการเปลี่ยนแปลงข้อมูล |

**Main flow (วางแผน, API `GET /admin/bookings` มีแล้ว)**
1. Admin login แล้วเห็นเมนู "จัดการการจอง"
2. ระบบแสดงการจองทั้งหมด เรียงตามวัน/เวลา พร้อมสถานะ
3. Admin ค้นหาตามรหัสนักศึกษา หรือกรองตามห้อง / วันที่ / สถานะ

**Alternative flow**
- **1a ผู้ใช้เป็นนักศึกษา:** ระบบปฏิเสธ (403)

## UC7, UC8 (Backlog)
- **UC7 จัดการข้อมูลห้อง:** Admin เพิ่ม แก้ไข หรือปิดห้องชั่วคราว (`room.is_active = FALSE`) → ห้องที่ปิดไม่แสดงในตารางจอง
- **UC8 จัดการรายชื่อ Blacklist:** Admin ดูรายชื่อที่ถูกระงับสิทธิ์ และปลดระงับเมื่อมีเหตุจำเป็น
